# Port status

## Objective and source

Port the complete local `~/Work/Baileys` library to Rust, preserving WhatsApp wire behavior and offering idiomatic Rust equivalents of its public functionality. Passing foundation tests does not establish that the full port is complete.

Source: upstream `0af2386292907f7d9742d8d41f830d8c48208fa1`, package 7.0.0-rc14. Source checkout was clean at initialization. No upstream files were modified.

## Implemented increment

- Cargo library scaffold, reproducible dependency lockfile, and upstream MIT license.
- Complete `WAProto/WAProto.proto` schema vendored unchanged; build-time Prost bindings, with temporary enum normalization documented in README.
- JID parsing/encoding, normalization, device transfer, domain classification, same-user comparison, and bot classification.
- Binary node content model, insertion-ordered attributes, typed child accessors, integer extraction, and structured stanza errors.
- Binary stanza encoding and decoding: all four token dictionaries, packed hex/nibble strings, device/domain JIDs, pair JIDs, decoder-only Facebook/interop JIDs, nested lists, UTF-8, all binary length forms, and compressed incoming stanzas.
- Bounded decoding and truncated input handling.
- AES-256 GCM/CTR/CBC, IV-prefixed CBC, SHA-256/MD5, HMAC-SHA-256/512, HKDF-SHA-256, and pairing-code PBKDF2.
- X25519 key generation/agreement, libsignal-compatible deterministic Curve25519 signatures, Signal public-key encoding, and signed prekey generation. Private key debug output is redacted and owned keys are zeroized on drop.
- Noise transcript authentication/key mixing, server certificate-chain signatures and issuer checks, encrypted client static key, payload encryption, independent transport counters, protocol/routing introductions, and incremental frame reassembly across handshake/transport transitions.
- Noise rejects tampered certificates, authenticated ciphertext changes, replayed transport frames, unverified transport initialization, excessive frame sizes, and nonce counter wraparound.
- Authentication credential initialization and models, contact/account/history metadata, authenticated-user assertion with a 401 error, BufferJSON byte encoding, and protobufjs integer compatibility without 64-bit precision loss.
- Typed values for all ten upstream Signal key-store categories, including runtime JSON session records and protobuf app-state keys.
- SQLite auth storage with atomic key batches and credential/key transactions, nested transaction reuse, read caching, rollback, cross-handle serialization, crash recovery, private file creation, and credential validation on resume.
- Prekey allocation/reuse and upload acknowledgement with atomic persistence, plus upstream's loaded-before-deletion transaction rule.
- Optional bounded TTL key cache that avoids publishing failed backend writes.
- Baileys multi-file JSON import/export, preservation of unknown credential/contact fields, explicit recovery of ambiguous IDs, and collision detection.
- Browser/companion descriptions, pinned version/origin/socket constants, login and registration ClientPayload generation, MD5 build hashes, encoded companion history-sync capabilities, and pairing QR data.
- Standard/hosted successful-pairing validation (ADV HMAC and account signature), signed device-identity reply generation, and application of pairing credential updates.
- Async TLS WebSocket/Noise connection with one Tokio owner, request correlation, bounded pending queries, timeouts/cancellation, keepalive, connection/node/QR/credential events, explicit close/logout, and reconnect using persisted state.
- QR rotation/expiry, standard/hosted pair-success integration, phone pairing exchange/acknowledgement, persistent routing info, offline preview/batch events, server-adjusted unified-session telemetry, and network prekey count/upload/acknowledgement, exponential retries, activation, and digest fallback.
- Seven built-in USync query protocols (devices/contact/status/disappearing mode/bot/LID/username), typed result parsing, device JID extraction, socket query/contact/LID helpers, encrypt-IQ/retry-receipt prekey parsing, key-request construction, and asynchronous session establishment with blocking-executor injection.

## Completion evidence required

Each upstream public export and socket operation must map to implemented Rust functionality or a justified language-specific equivalent. Protocol/crypto/sync/media paths need deterministic interoperability evidence, not only Rust roundtrips. Mock peer tests must demonstrate pairing/authenticated connection, message send/receive, group encryption, auth persistence, and reconnect. Live account validation, if available, must be clearly distinguished from mocked validation. Completion remains unproven until the full source surface and runtime behavior have been audited.
